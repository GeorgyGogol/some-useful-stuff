# Генерирование ssh ключей

Для связки своего git на локальном компьютере с удаленным сервером с репозиториями в основном используется способ аутентификации пользователя по ssh.
Для такой фитчи нужно сгенерировать свои ключи ssh.

## Синопсис

Для того чтобы предоставить открытый ключ, каждый пользователь в системе должен его сгенерировать, если только этого уже не было сделано ранее.
Этот процесс аналогичен во всех операционных системах.

Обычно ключи сохраняются в директории пользователя в поддиректории .ssh, в файле id_rsa или id_dsa (приватный, личный ключ) с сопутсвующим файлом расшарением .pub (публичный ключ).
Для их генерации используется программа ssh-keygen, которая уже есть в ОС Linux/MacOS или поставляемая вместе с git для Windows.

```sh
ssh-keygen -o
```

Сначала программа попросит указать расположение файла для сохранения ключа (.ssh/id_rsa), затем дважды ввести пароль для шифрования.
Если вы не хотите вводить пароль каждый раз при использовании ключа, то можете оставить его пустым или использовать программу ssh-agent.
Если вы решили использовать пароль для приватного ключа, то настоятельно рекомендуется использовать опцию -o, которая позволяет сохранить ключ в формате, более устойчивом ко взлому методом подбора, чем стандартный формат.

После генерации необходимо предоставить свой *публичный* ключ (это который .pub) предоставить серверу, на котором хранятся репозитории.
Открытый ключ выглядит примерно так:

```txt
ssh-rsa <many chars> <user email>
```

Это позволит иметь доступ к серверу с удаленными репозиториями для обмена данными с ним

## ssh-keygen

По умолчанию ssh-keygen генерирует ed25519 ключи.
Но утилита универсальная и может генерировать ключи доступа различными способами.
Можно попросить явно сгенерировать ключ с нужным типом шифорования, например сгенерировать ключ RSA4096:

```sh
ssh-keygen -b 4096 -t rsa
```

Есть еще флаг -f, через который передается название файла, в который будет помещен ключ.

## Заметка по Unix-подобные ОС

Можно не заморачиваться с открытием файла и сразу скопировать его содержимое.
В терминале, после генерации вводим команду:

```sh
pbcopy < ~/.ssh/id_rsa.pub
```

Публичный ключ у нас в буфере обмена, можно копипастить на сервер.

## Хранение нескольких ключей

На одном компьютере можно хранить несколько ключей.
Это может применяться для работы с несколькими серверами с одного устройства.

1. Генерируем следующий ssh-ключ с уникальным названием (чтобы другие не перетереть)
2. Настраиваем файл ~/.ssh/config

```
Host <host_name>
    HostName <host_name>
    IdentityFile ~/.ssh/<key-file-name>
```

3. Выполняем операцию git fetch для новодобавленного сервера
4. git говорит, что видит его впервые. Выполняем подтверждение

В результате у нас сконфигурирован еще один ключ для другого сервера.
