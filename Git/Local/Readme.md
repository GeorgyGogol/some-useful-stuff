# Локальный репозиторий

Репозиторий (рабочая копия) на компьютере. Вообще, локальный репозиторий состоит из двух частей - рабочая директория и директория ".git". Рабочая директория соответствует текущей распакованной ветке (HEAD репозитория), а в .git хранится информация о репозитории в целом.

## Настройка

После установки необходимо выполнить настройку (конфигурирование) git - установить пользователя, его адрес, под которым будет выполняться работа. Выполняется это с помощью следующих команд:

```sh
git config <--global> user.name <name>
git config <--global> user.email <email>
git config user.name
git config user.email
```

1. Устанавливает имя пользователя
2. Устанавливает адрес электронной почты пользователя
3. Отображает установленное имя пользователя в текущем репозитории
4. Отображает установленный адрес электронной почты пользователя в текущем репозитории

* Опция "--global" выполняет настройку в глобальном плане - для всех репозиториев без дополнительных переопределений

## Инициализация

```sh
git init
git init --bare
```

1. Инициализация репозитория в текущей директории
2. Создание "голого" репозитория в текущей директории, без рабочей директории. Т.е. получаем что-то типа репозитория-сервера, который может только хранить файлы. Об этом можно узнать [тут](LocalRepo.md)

## Генерирование ssh ключей

Для связки своего git на локальном компьютере с удаленным сервером с репозиториями в основном используется способ аутентификации пользователя по ssh.

Для того чтобы предоставить открытый ключ, каждый пользователь в системе должен его сгенерировать, если только этого уже не было сделано ранее. Этот процесс аналогичен во всех операционных системах.

Обычно ключи сохраняются в директории пользователя в поддиректории .ssh, в файле id_rsa или id_dsa (приватный, личный ключ) с сопутсвующим файлом расшарением .pub (публичный ключ). Для их генерации используется программа ssh-keygen, которая уже есть в ОС Linux/MacOS или поставляемая вместе с git для Windows.

```sh
ssh-keygen -o
```

Сначала программа попросит указать расположение файла для сохранения ключа (.ssh/id_rsa), затем дважды ввести пароль для шифрования. Если вы не хотите вводить пароль каждый раз при использовании ключа, то можете оставить его пустым или использовать программу ssh-agent. Если вы решили использовать пароль для приватного ключа, то настоятельно рекомендуется использовать опцию -o, которая позволяет сохранить ключ в формате, более устойчивом ко взлому методом подбора, чем стандартный формат.

После генерации необходимо предоставить свой *публичный* ключ (это который .pub) предоставить серверу, на котором хранятся репозитории. Открытый ключ выглядит примерно так:

```txt
ssh-rsa <many chars> <user email>
```

Это позволит иметь доступ к серверу с удаленными репозиториями для обмена данными с ним

### Альтернатива

```sh
ssh-keygen -b 4096 -t rsa
```

Это заклинание явно генерирует ключ RSA4096. Фишка в том, что утилита универсальная и может генерировать ключи доступа различными способами. Так, без уточнений, будет сгенерирован ed25519 ключ.

### Заметка про мак

В терминале, после генерации вводим команду

```sh
pbcopy < ~/.ssh/id_rsa.pub
```
