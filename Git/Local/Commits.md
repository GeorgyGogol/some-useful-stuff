# Коммиты

Сообщения фиксации индекса.

Рекомендуемая длина сообщения коммита: 74 символа, 50 для первой строчки. Обусловлено размерами командной строки, так повелось.

## Немного подробнее про термины

Коммит - это фиксирование состояния репозитория. Оно состоит из нескольких частей: изменения, сообщение, автор, время, hash...

Изменения коммита - это те файлы, которые были изменены и добавлены в "индекс" - отслеживаемые git файлы.

Индекс - это отслеживаемые изменения в файлах до создания коммита. Такой промежуточный этап по переходу в состояние "изменения зафиксированы".

Сообщение коммита - это небольшое пояснение, что было сделано, для удобства навигации.

Автор - это пользователь, который сделал коммит. Так же, есть возможность "подписать" коммит другим пользователем (signed-off). Тогда в истории изменений должно отображаться имя пользователя, которым подписались (я так не делеал). Вместе с тем, информация о пользователе, фактически сделавшем коммит, так же остается и его можно извлечь.

Время - это то, во сколько был сделан коммит. Как правило, оно совпадает с фактическим временем, но его можно изменить. Фактическое время также, как и фактического автора, можно извлечь.

## Как делать коммит

Коммит делается следующим образом:

```sh
<git checkout -b <newBranchName>>
git commit < -m 'message' > < --amend >
```

1. checkout - команда переключения на новую ветку newBranchName, если изменения на самом деле относятся к новой ветке
2. m - сообщение, без вызова редактора
3. amend - исправление предыдущего коммита

При отсутствии флага '-m' идет вызов текстового редактора для ввода комментария. Символы "#" учитываются как комментарии и не включаются в сообщение. По-умолчанию используется текстовый редактор Vim, поставляемый вместе с git (на Windows это точно).

## Добавление файла в индекс

Нельзя просто так сделать пустой коммит. Коммит - это один из этапов развития проекта, формирующий историю. Как правило, это справделиво для обычных случаев.

* Сделать: тут должен быть мем

Для добавления файла нужно воспользоваться:

``` sh
git add <file_name>
# or add all files, except ignored:
git add .
```

На месте *file_name* можно написать название директории, в таком случае будет добавлена директория целиком, за исключением игнорируемых файлов.

Для принудительного добавления игнорируемого файла:

```sh
git add -f <ignored_file_name>
```

## Исключение файлов из отслеживаемых

Для исключения:

```sh
git rm <file_name>
git rm --cached <file_name>
```

1. Удаляет файл из индекса и удаляет в целом
2. Удаляет файл только из индекса, оставляя файл нетронутым

## Восстановление файла

Если ВДРУГ было решено отказаться от изменений, файл можно восстановить до его предыдущего состояния (вроде как индекс учитывается)

Для восстановления:

```sh
git restore <file_name>
```

## amend

Флаг исправляет предыдущий коммит, НО из-за этого создается новый. Новый хэш, дата создания. От старого остается дата коммита (её можно изменить). Это не критично, если изменения еще не были опубликованы (не отправлены в удаленное хранилище). Но если уже отправлены, то следующая команда отправки ветки должна выполняться с флагом -f, что перезаписывает коммит (и историю) в удаленном репозитории. Собственно, по этой причине практика исправления не рекомендуется. Вместо этого лучше всего сделать коммит "сверху", который исправляет ошибки.

## Stash

Что-то вроде специального коммита, в который включается все состояние рабочей директории (за исключением игнорируемых файлов), без сообщения и фиксации в текущую ветку. Это временное хранилище изменений и используется для сохранения состояния рабочей копии.

Может быть полезно для переключения между рабочими изменениями и другой веткой, например, для уточнения состояния на другой ветке, подтягивания (git pull) состояния с удаленного репозитория или переключения на более критичную и экстренную задачу.

Колдуется командой:

```sh
git stash
```

При выполнении команды проиндексированные изменения рабочей копии падает в стэш, при этом сама рабочая копия очищается (т.е. сохраняется в стэше)

Для возвращения изменений даем команду

```sh
git stash pop
```

Команда извлекает изменения из стэша и сбрасывает его состояние

Есть вариант без сброса стэша:

```sh
git stash push
```

Это должно просто восстановить состояния из стеша на текущей ветке, без его сброса

Для простой полной очистки стэша:

```sh
git stash drop
```
